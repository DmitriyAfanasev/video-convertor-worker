# MiniTube: Go + FFmpeg

Небольшой учебный видеохостинг: браузер загружает исходник, Go кладёт задачи в очередь,
несколько воркеров параллельно запускают FFmpeg, а страница показывает готовые варианты
1080p, 720p, 480p и 360p.

## Быстрый запуск

Нужны Go 1.27+ и `ffmpeg` в `PATH`:

```bash
go run .
```

Открыть <http://localhost:8080>.

Либо всё вместе в Docker:

```bash
docker compose up --build
```

Настройки окружения:

- `ADDR` — адрес HTTP-сервера, по умолчанию `:8080`;
- `DATA_DIR` — каталог видео и метаданных, по умолчанию `./data`;
- `WORKERS` — число одновременно работающих конвертеров, по умолчанию `2`;
- `MAX_UPLOAD_MB` — предел одной загрузки, по умолчанию `2048`.

## Как это устроено

`POST /api/videos` сохраняет исходник и быстро отвечает `202 Accepted`. Четыре независимые
задачи попадают в buffered channel. Каждый worker — goroutine, но тяжёлая работа выполняется
отдельным процессом FFmpeg. Метаданные атомарно пишутся в `data/<id>/metadata.json`, поэтому
список роликов переживает перезапуск. Сами незавершённые задания после рестарта помечаются
ошибкой: надёжная повторная доставка — задача настоящего брокера сообщений.

HTTP file server поддерживает Range-запросы, поэтому браузер умеет перематывать MP4 без
скачивания файла целиком. Масштабирование не увеличивает исходник: маленькое видео не будет
искусственно растянуто до 1080p.

## Что поменять для production

Эта версия специально запускается на одной машине. В production API обычно не принимает
гигабайты через себя: оно выдаёт signed URL, клиент грузит исходник напрямую в S3/MinIO,
а API публикует задания в Kafka, RabbitMQ, SQS или Redis Streams. Отдельный autoscaling-пул
FFmpeg workers берёт задания, сохраняет HLS/DASH-сегменты в object storage и обновляет запись
в PostgreSQL. CDN раздаёт сегменты, а reverse proxy отвечает за TLS, rate limit и auth.

Также понадобятся: проверка контейнера через ffprobe, антивирус/изоляция FFmpeg, retries с
идемпотентностью, лимиты CPU/RAM/диска, метрики и tracing, очистка исходников, превью,
субтитры и HLS adaptive bitrate. Для массового просмотра HLS/DASH предпочтительнее четырёх
отдельных MP4: плеер сможет автоматически менять качество по скорости сети.
